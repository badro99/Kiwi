# Wave S · decision gaps of the tenth blind rating (26 October 2026)

The tenth blind rating (code f408fee2) named 10 gaps that need a product rule. The lead ruled each one the conservative way; the owner can reverse any line. Format: `feature · gap · decision · why`.

Accepted as designed (no code change):
- planning · notices kept to the last 200 · the cap stays · a planning document must stay small enough to sync on a phone; older notices were already read.
- serveur · device notifications kept to the last 100 · the cap stays · the device history is a working list, not an archive.
- tables · local recovery lookup keeps the last 20 matching sessions · the cap stays · the server holds every session; the local list only recovers a till that lost its connection.
- stock · two tills selling the last unit offline both succeed, stock goes negative and is reconciled · the offline-first rule wins over a live cross-till reservation · a till must sell without a network; refusing a sale at the counter costs more than a reconciliation line.
- creditbook · advance refunds by bank transfer only · stays until a cash-session rule exists · a cash refund would have to be attributed to a till session, which is a separate decision.
- shopify · inbound stock capped to available units, overflow listed as exceptions · the cap stays · an external shop must not create negative stock in the till without a person seeing it.

Implemented:
- boutiquetill, returns · the returns journal keeps 500 local entries · the dashboard returns register is built from the server's refund events; the local log stays a 500-entry cache · a long-running shop must see every return.
- employee · an offline punch older than the 12-hour acceptance window is not replayed · it is kept and shown to the employee as "to be corrected by a manager", naming the day and time · an automatic late replay could falsify payroll; a silent drop loses worked time.
- landing · signup does not carry the plan chosen on the landing · signup records it as a requested plan, shown to the operator, who confirms billing; the account still starts on basic · billing stays manual (no payment rail in phase 1), the operator no longer has to ask.
