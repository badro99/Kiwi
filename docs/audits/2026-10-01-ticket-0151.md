# #0151 · Menu and inventory workspace redesign

Date: 2026-10-01. Runtime commit: `35fc3e9176a4d0fc9fcb0113e4b3924b01526985`. Untouched upstream base: `bfc6f3d7ae2328874294a0a6b6a927e40cd0a2bd`.

## Scope and diagnosis

All five original ticket attachments were retrieved from the live board and inspected individually. The requested ticket connector is not enabled in this session; the authenticated board provides the same originals and its normal Testing transition. No other ticket is included in this change.

| Surface | Root cause | Implemented change |
| --- | --- | --- |
| Menu toolbar | Section mutation controls all competed with the primary action. | One New item button and one section-tools sheet. New/rename/delete use existing product flows. Reorder uses real drag handles or an accessible position selector. |
| Menu items | Native one-column override outranked the responsive grid; repeated action rows consumed card space. | Two columns on phone, three/four at wider breakpoints. Media/placeholder, clamped name, price, explicit availability, compact formula/options/nutrition metadata. Tap edits; one overflow offers availability, archive/restore, formula reuse and deletion. |
| Supplier list/detail | Desktop table compressed into a phone; the detail renderer referenced undefined variables and displayed invented delivery/chart fixtures for every supplier. | Phone supplier cards, unchanged wide table. Detail uses saved procurement receipts or grouped supplier-scoped receipt movements. Missing deliveries are explicitly unrecorded, never estimated. ISO dates sort correctly; zero spend avoids NaN. |
| Items & stock | Sub-tabs and two filter rows clipped; search competed with view controls; card stock cues were color-only. | Separate search/view rows, dense mobile list with sorting, card toggle with textual stock state. Wide sortable table retained. Catalogue/waste/history labels localized. |
| Inventory overview/orders/tabs | Stacked skins imposed conflicting density and overflow. | Shared type/spacing/radius, compact KPIs, scrollable lens rails with edge fades and active-item reveal. Order-history rows become mobile cards; wide table retained. |

The real renderers are `assets/restaurant-menu-workspace.js` and `assets/stock.js`, not the older menu implementation in `pages-pro.js`. Shared catalog CSS intentionally outranks the three dashboard skins. Native single-column CSS was removed rather than adding another competing override. The existing Liquid Lens implements selection; no new selection system or icon paths were introduced.

## Data and behavior safety

- Local isolated demo models only. Browser and simulator harnesses block merchant API/auth traffic. No production D1 writes, real merchant edits, account deletion, credentials or PIN entry.
- Menu fixtures: **200 TEST KIWI items**, four sections including an empty section, two subsections, long French/English/Arabic names and mixed availability. Simulator fixtures have at least 60 TEST KIWI items.
- Native QA uses a **separate private app identifier** (`com.kiwios.pro.qa0151`), the existing Swift shell and a freshly bundled frontend. The installed merchant/distribution app is untouched.
- Identical renders retain DOM nodes and rail position. Search preserves focus/caret after real keystrokes. Changed selections reveal themselves instead of snapping every poll back to the first chip.
- Sheets close through the shared modal API, then invoke the original handler. Background scroll locks are released; no manually removed overlays or nested handoff sheets.
- Supplier accounting, inventory posting, procurement, prices, modifier models and permissions were not rewritten. No database migration.
