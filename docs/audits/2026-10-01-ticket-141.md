## Implemented

### Cashier invoice

- `makeSaleInvoice` now uses an explicit server sale ID when present, otherwise the same tenant-scoped `KiwiLive.saleIdFor` and canonical alias as the money sender. A local cashier journal UUID is not a D1 sale ID. Imported journal rows preserve the server ID and exact cents.
- Preserve the journal's original timestamp, including its `Date` value. The old adapter supplied `time` while the invoice builder read `ts`, producing the current time instead of the receipt time.
- Reserve the output window synchronously under the last actual click, before awaiting D1. If customer information is needed, show that prompt first and reserve under its confirm/skip click, so a blank tab does not hide the unanswered prompt.
- A blocked popup produces a visible, dismissible document viewer with print/PDF controls, instead of a warning with no document.
- Bound the invoice POST and response-body read at twelve seconds. Failure closes the waiting window and leaves numbering to the server; retry remains the existing one-invoice-per-sale operation.
- Accept only a server invoice with a non-empty number and positive integer sequence. Keep invoice cache per merchant, and refuse to display/cache an old merchant's response after a store switch.
- On iOS, `KiwiPrinterSocket.exportInvoice` renders an A4 PDF with UIKit's page renderer and presents Save to Files / Print / Share. Nothing is shared automatically. The temporary PDF is protected and removed when the activity completes. Presenting the sheet is not proof that a user saved or printed it.

### Dashboard feed

- Bound the entire feed GET and JSON read at twelve seconds. Previously an unresolved request kept `busy` true indefinitely; focus/reconnect could only set `again` and could not resume the pump.
- Late responses cannot win a completed timeout race or update a different active store.
- Drain full fifty-row pages immediately at the live edge as well as during initial backfill. Previously the live/background path could wait another normal interval for every page.
- Read with included credentials and `cache: no-store`; the native API-base rewrite must not lose its session cookies. Do not describe refused/invalid responses as a fresh successful read; expose `feedError` through Live Link status.

These are reproduced client failure modes, not a claim that every minute of the reported production delay has been attributed to them.
