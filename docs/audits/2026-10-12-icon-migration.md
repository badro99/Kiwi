# Icon migration · Lucide names → Material Symbols Outlined · 2026-10-12

CLAUDE.md §4 locks the icon set: Google Material Symbols, Outlined 400, grade 0,
optical size 24, vendored in `assets/icons/material/`. This audit takes stock of
what the shipped surfaces actually draw, and stages the migration so that no
call site breaks along the way (CLAUDE.md §2: a shipped surface is migrated in
stages, never as a side effect).

## What was true before this pass

- **The Lucide library had already left.** Since `025a4246` (2026-08-21),
  `assets/lucide.min.js` was not Lucide. It was a shim generated by
  `tools/build-material-symbols-runtime.mjs` that turned `<i data-lucide="…">`
  into Material paths. What it got wrong:
  - It drew **Rounded** glyphs, fetched from gstatic at build time. That is not
    the locked Outlined set, and not the folder the dashboard reads since
    `6c1e3eb1`, so the dashboard was mixing Outlined and Rounded.
  - It did not read from the vendored folder, so the 113 KB of paths could not
    be traced back to files in the repo.
  - **An unknown name rendered as a "?" (`help`) without any warning.** The
    waiter app's "order done" notification asks for `circle-check`, which no
    alias covered, so it has drawn a "?" in production.
  - The file name and the global (`window.lucide`) still said Lucide.
- **The call sites** are 1 749 `data-lucide` attributes in 38 files, using
  198 distinct literal names plus 82 dynamic sites (ternaries, `${x.icon}`,
  `*_MATERIAL_ICONS` maps that already pass Material names through). Heaviest:
  `pos-maison.js` 227, `kiwi-caisse.html` 175, `pos-boutique.js` 174,
  `pos-gym.js` 109, `pressing-caisse.js` 91, `kiwi-serveur.html` 91.
  `lucide.createIcons()` is called from 31 files (66 times in the till alone).
- **Hand-drawn stroke SVGs** (`viewBox="0 0 24 24" stroke="currentColor"`)
  remain on several surfaces. About 300 occurrences, led by `pages-pro.js` (88),
  `interactive.js` (26), `pages.js` (20), `kiwi-caisse.html` (20),
  `pressing-dashboard.js` (12), `features.js` (12). Some of them are charts or
  rings rather than icons. Stage 3 deals with them.
- The marketing site (`index.html`, `fr/`, `en/`, `ar/`, guides) is a Next.js
  export that inlines lucide-react SVGs from its own build. It is built
  outside this repo and is not covered here.

## Stage 1 · this pass

- **The 237 vendored Outlined files are the source.** 142 were added: 134
  glyphs the old shim drew and 8 closer matches (see below), each fetched from
  the README's `curl` URL and left byte-identical. The 7 Rounded targets the
  closer matches replaced are not vendored, since nothing asks for them.
- **`tools/build-material-icons.mjs` generates `assets/material-icons.js`**
  from those files and from `tools/material-icon-aliases.json`, the single
  Lucide → Material table. The DOM contract is unchanged (inline `<svg>`,
  `fill="currentColor"`, `data-lucide` and the `lucide lucide-<name>` classes
  kept, `data-material-symbol` added), so no CSS selector moves. Only the
  geometry changes, from Rounded to Outlined.
- **New code writes `<i data-icon="print">` with a Material name**, or
  `KiwiIcon.svg('print', 18)` in a template string. `window.lucide.createIcons()`
  is kept as a compatibility entry point. A name that does not resolve still
  draws the "?" so the layout holds, but it now `console.warn`s once and is
  listed in `KiwiIcon.missing`.
- **The six pages** (`kiwi-caisse.html`, `kiwi-serveur.html`, `dashboard.html`,
  `kiwi-order.html`, `OrderPro.html`, `cafe-atlas-qr.html`) and the SW precache
  load `assets/material-icons.js`. `assets/lucide.min.js` and its builder are
  deleted.
- **The gate, `tools/material-icons-test.mjs`, is wired into `check.js`.**
  - Every vendored file is a single-path Material glyph.
  - The runtime and the table below are exactly what the generator produces.
  - Every icon name a call site asks for resolves to a vendored glyph. That
    covers literal attributes, the branches of a dynamic one, `icon: '…'` data,
    `*ICONS` tables and `…Icon()` helpers.
  - No page loads the old shim.
  - **No file gains a `data-lucide`.** Per-file counts are frozen in
    `tools/data-lucide-baseline.json`. They can only go down
    (`node tools/build-material-icons.mjs --ratchet` lowers them). A new file
    with a `data-lucide` fails the gate.

## Stage 2 · next: rewrite call sites to `data-icon`

One file per commit, heaviest first, each one verified on its surface:
replace `data-lucide="<lucide>"` with `data-icon="<material>"` using the table
below, then `--ratchet`. The edit is mechanical, so it is a good fit for a cheap
model. When the baseline reaches zero, delete the alias table, the
`data-lucide` branch of the runtime and `window.lucide`.

## Stage 3 · after: hand-drawn stroke SVGs

Replace each inline stroke icon with its Material glyph through
`KiwiIcon.svg()` or `data-icon`. Skip charts and progress rings. Then add a
gate for `stroke="currentColor"` on a 24-grid `<svg>`.

## How it was verified

The till (`kiwi-caisse.html`) was checked at 390 px (phone), 834 px (iPad) and
1440 px (desktop), and the waiter app (`kiwi-serveur.html`) at phone width,
each in light and dark, on the local stack with the old service worker
unregistered and every cache cleared. On each screen `KiwiIcon.missing` was
read, and every `svg[data-material-symbol]` was checked for a non-empty path
and a non-zero box.

how the `*_MATERIAL_ICONS` maps already pass Material names through.
